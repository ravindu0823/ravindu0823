# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this repo is

The GitHub profile README for `ravindu0823`. The repository name matches the username, so GitHub renders `README.md` on https://github.com/ravindu0823. Besides the README there is a small, dependency-free Node renderer (`scripts/`) that draws the profile's SVG cards, and one workflow that rebuilds the data-driven cards.

## Commands

Node 20+ only. There is no `package.json` and no npm dependency, by design.

```bash
node --test scripts/github.test.mjs                 # unit tests (streaks, language weighting, fail-closed check)
node scripts/render.mjs static assets               # banner + tech-stack cards -> assets/ (commit the output)
STATS_TOKEN="$(gh auth token)" node scripts/render.mjs stats <dir>   # activity + languages cards, for a local preview
```

`static` downloads icons from devicon (jsDelivr, pinned to `v2.17.0`) and embeds them as data URIs, so it needs network. Re-run it and commit `assets/` after any change to `banner.mjs`, `stack.mjs`, `svg.mjs` or `theme.mjs`. CI never regenerates `assets/`.

## How the pieces fit

- **Two render paths.** `assets/` holds static cards (banner, four stack cards) that are generated locally and committed to `main`. The stats cards and the contribution snake are generated by `.github/workflows/profile-assets.yml` and force-pushed to the orphan `output` branch. The README loads both through absolute `raw.githubusercontent.com` URLs.
- **Every card comes in `-dark` and `-light`**, selected in the README with `<picture><source media="(prefers-color-scheme: dark)">`. On github.com the switch is done by GitHub's `<themed-picture>` script, following the viewer's GitHub theme.
- **Cards are 415px wide** (`CARD_WIDTH` in `theme.mjs`). The profile README column is 846px at desktop widths (measured), so two cards fit per row there and drop to one per row on smaller screens. Keep new cards at this width.
- **Fonts.** An SVG shown through `<img>` cannot load web fonts, so text uses system font stacks. `text()` in `svg.mjs` clamps with `textLength` when the estimated width exceeds the box.
- **Animation is decoration only.** Anything that carries data (the stats cards) is static. Animated geometry in the banner has its finished value as the base attribute, so a renderer that skips SMIL still shows the whole kicker. A renderer that freezes at t=0 shows the start of the animation, which is why data never animates.
- **Stats privacy.** `github.mjs` reads `commitContributionsByRepository`, which includes private client repositories (most of the owner's work). Only aggregates may leave that module. Never render or log a repository name.
- **Fail closed.**
  - `validate()` refuses empty or contradictory data.
  - With `STATS_EXPECT_PRIVATE=1`, as the workflow sets it, `validate()` also refuses a token that can no longer see private work.
  - The workflow restores the last published files into `dist/`, then runs the generators with `continue-on-error`. A failure republishes yesterday's cards, and a final step turns the run red.
  - A failure to reach the `output` branch stops the run before anything is published.
  - Only whitelisted file names are published.
- **Workflow tokens.**
  - The `TOKEN` secret (the owner's classic PAT: `repo`, `read:user`) is used only to read contributions.
  - The push to `output` uses the built-in `github.token`, passed as an env-configured auth header and masked.
  - Actions are pinned by commit SHA, with the version in a comment.
- **Stale cards.** GitHub disables scheduled workflows in public repos after 60 days without repository activity. Whether the bot pushes to `output` count as activity is UNKNOWN. If the "updated" date on the cards stops moving, re-enable the workflow in the Actions tab.

## Editing the README

- GitHub's sanitizer strips `<style>`, `<script>` and `class`, so lay out with `align`, `width` and `<picture>`.
- Don't wrap a `<picture>` in `<a>`. GitHub auto-links every image, and the nested anchor makes it move the `<img>` out of the `<picture>`, which breaks both the link and the theme switch.
- `> [!NOTE]` alerts came back as literal text from the markdown API in `markdown` mode, the mode that does match repository rendering for `<themed-picture>`. That was not re-checked on the live profile, so use a plain blockquote.
- shields.io no longer has LinkedIn or Outlook logos (simple-icons removed them). Those two badges carry inline base64 SVG logos.
- Preview the README faithfully: `gh api -X POST markdown` with `{"mode":"markdown"}` returns the repository-file HTML. `"gfm"` mode renders like a comment, turns newlines into `<br>`, and is not representative.
- Featured-work text comes from the owner's CV. 747 Live work is described neutrally, with no gambling terms. Keep it that way, and don't add numbers or claims that aren't in the CV or verifiable on GitHub.
- Windows has no flag-emoji glyphs (🇱🇰 renders as "LK"), so avoid flag emoji.
